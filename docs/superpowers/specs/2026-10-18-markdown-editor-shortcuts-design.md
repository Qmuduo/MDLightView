# Markdown 编辑快捷工具设计

日期：2026-10-18

## 目标

让手机上的 Markdown 源码编辑更顺手，减少用户手动输入标记符号的次数。沿用当前单栏源码编辑器和本地草稿流程，不替换编辑器，不改变原文件保护方式。

## 采用方案

在源码编辑区底部、现有“阅读预览”和“另存副本”操作上方增加一排可横向滚动的快捷工具。工具栏在软键盘打开时仍可见，点击工具后继续保留编辑焦点和键盘。窄屏可横向滚动；每个操作提供明确的无障碍名称。

工具包括：加粗、斜体、标题、无序列表、有序列表、引用、代码和链接。代码工具对单行文本应用行内代码，对多行文本应用围栏代码块；没有选中内容时插入空围栏并将光标放在块内。标题默认为二级标题，并作用于当前行。列表和引用作用于所选的每一行；没有选择时作用于光标所在行。

## 输入与光标行为

- 加粗、斜体和行内代码：选中内容时包裹选中文本；无选区时插入成对标记，并把光标放在标记中间。
- 标题、列表和引用：按行添加对应 Markdown 前缀；已有相同前缀时移除该前缀，便于切换格式。
- 链接：选中文本时将其转换为链接文本，并把光标放进 URL 槽位；无选区时插入链接模板并选中链接文字占位符，用户可直接替换。
- 选择范围跨多行时，列表和引用逐行处理，保持原始换行与行内文本。
- 应用命令后更新源码和 TextInput 选择范围，不重置整篇文档或丢失键盘焦点。

## 结构与数据流

- `Reader` 继续拥有受控的多行 `TextInput`、当前源码与选区，并将格式化命令应用到当前文本。
- 新增 `EditorToolbar` 负责展示横向滚动的格式按钮并上报命令；不负责文档持久化。
- 新增纯文本命令模块（例如 `editorCommands.ts`），负责按选区计算更新后的 Markdown 与光标/选区位置。
- 命令产出的源码沿用现有 `onChange` 路径，触发 `DraftWriter` 自动保留；预览继续使用 `buildReaderPage`，另存副本仍走现有读回校验流程。
- 不增加富文本编辑器依赖，也不引入文件回写、版本历史、表格生成或分栏预览。

## 异常与边界

空文档、行首/行尾选区、跨行选区、文件末尾无换行、已有 Markdown 前缀都需要保持有效文本和可预测的光标位置。格式化只改当前草稿；用户退出到阅读或保存副本时仍遵循现有草稿保留与副本另存行为。

## 验收方式

在 Android 编辑界面手动确认：软键盘打开时快捷工具可见；选中文本和无选区两种情况下格式操作正确；链接、行格式和代码模板的光标/选区位置合适；快捷操作后可继续输入；预览呈现正确；返回后草稿可恢复；浅色与深色主题均可读。类型检查与 Android 导出沿用项目现有流程。此次设计不新增自动化测试。
